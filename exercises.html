6장Parsing Expressions

토큰 나열을 문법 규칙에 맞는 AST로. 출발 문법:

grammar
expression → equality ;
equality   → comparison ( ( "!=" | "==" ) comparison )* ;
comparison → term ( ( ">" | ">=" | "<" | "<=" ) term )* ;
term       → factor ( ( "-" | "+" ) factor )* ;
factor     → unary ( ( "/" | "*" ) unary )* ;
unary      → ( "!" | "-" ) unary | primary ;
primary    → NUMBER | STRING | "true" | "false" | "nil" | "(" expression ")" ;

구현 6-1. 콤마 연산자

하나의 표현식 자리에 콤마로 구분된 여러 표현식을 넣는다(함수 인자 목록 제외). 왼쪽을 평가해 버리고 오른쪽을 반환. C와 같은 우선순위·결합성.
  • 가장 낮은 우선순위 · 좌결합 → 문법 최상위에 comma 규칙을 끼우고 expression이 그것을 가리키게.
  • 구조가 왼쪽 , 오른쪽이라 새 AST 노드 없이 Expr.Binary 재사용.
grammar
expression → comma ;
comma      → equality ( "," equality )* ;          ← 새로 추가
java
private Expr comma() {
  Expr expr = equality();
  while (match(COMMA)) {
    Token operator = previous();
    Expr right = equality();
    expr = new Expr.Binary(expr, operator, right);   // 좌결합 누적
  }
  return expr;
}
// 런타임: visitBinaryExpr 에 한 줄
case COMMA: return right;   // left는 이미 평가됨(부수효과) → 버리고 right 반환
콤마 평가기 — 왼쪽은 버리고, 마지막만 값

구현 6-2. 조건(삼항) 연산자 ?:

?와 : 사이엔 어떤 우선순위가 허용되나? 전체는 좌결합인가 우결합인가?
  • 가운데: 어떤 표현식이든(괄호로 감싼 듯) → expression 전체 허용.
  • 결합성: 우결합. a ? b : c ? d : e = a ? b : (c ? d : e).
grammar
comma       → conditional ( "," conditional )* ;
conditional → equality ( "?" expression ":" conditional )? ;   ← else 가지는 재귀 = 우결합
java
private Expr conditional() {
  Expr expr = equality();
  if (match(QUESTION)) {
    Expr thenBranch = expression();                 // 가운데 = 전체 우선순위
    consume(COLON, "Expect ':' after then branch.");
    Expr elseBranch = conditional();                // 우결합 → 재귀
    expr = new Expr.Conditional(expr, thenBranch, elseBranch);
  }
  return expr;
}

1 ? 2 : 3 ? 4 : 5 가 우결합으로 묶이는 트리:

tree
   ?:                 1 ? 2 : (3 ? 4 : 5)
  /│\
 1 2 ?:               조건 1이 truthy → 2
     /│\              (오른쪽 ?: 는 평가되지 않음)
    3 4 5

구현 6-3. 왼쪽 피연산자 누락 에러 프로덕션

표현식 맨 앞에 이항 연산자가 오는 것을 감지해 에러로 보고하되, 오른쪽 피연산자는 적절한 우선순위로 파싱한 뒤 버려라.
입력결과
<= 5Missing left-hand operand.
* 3 / + 4 / == 2Missing left-hand operand.
- 4에러 아님 — -는 단항 부정으로 -4
java
// primary() 의 "Expect expression." 직전에 끼운다
if (match(BANG_EQUAL, EQUAL_EQUAL)) { error(previous(),"Missing left-hand operand."); equality();   return null; }
if (match(GREATER, GREATER_EQUAL, LESS, LESS_EQUAL)) { error(previous(),"Missing left-hand operand."); comparison(); return null; }
if (match(PLUS)) { error(previous(),"Missing left-hand operand."); term();   return null; }
if (match(SLASH, STAR)) { error(previous(),"Missing left-hand operand."); factor(); return null; }
// MINUS 는 제외 — 단항 '-' 로 유효. 단항 '+' 는 없으므로 '+' 는 항상 에러.

error(...)를 throw 없이 호출해 보고만 하고, 오른쪽을 마저 파싱해 버린 뒤 null을 반환하는 게 핵심.

7장Evaluating Expressions

AST를 후위 순회하며 값을 만든다. 동적 타입은 Object + 런타임 캐스트.

논술 7-1. 숫자 외 타입의 비교

다른 타입 비교를 허용하겠는가? 한다면 어떤 쌍을, 어떤 순서로?

제안: 문자열끼리(사전순)만 허용하고 혼합 타입은 런타임 에러로 막는다.

언어혼합 타입 비교 3 < "pancake"
Python 3TypeError — 막는다
JavaScript강제 변환 → NaN 비교 → 항상 false (직관 어긋남)
제안(Lox)문자열↔문자열만 허용, 나머지 에러
java
case LESS:
  if (left instanceof Double && right instanceof Double) return (double)left < (double)right;
  if (left instanceof String && right instanceof String) return ((String)left).compareTo((String)right) < 0;
  throw new RuntimeError(expr.operator, "Operands must be two numbers or two strings.");

구현 7-2. 한쪽이 문자열이면 +로 연결

"scone" + 4 → scone4. 한쪽이라도 문자열이면 변환해 연결.
java
case PLUS:
  if (left instanceof Double && right instanceof Double) return (double)left + (double)right;
  if (left instanceof String || right instanceof String) return stringify(left) + stringify(right);
  throw new RuntimeError(expr.operator, "Operands must be two numbers or two strings.");

stringify를 써야 4가 4.0이 아닌 4로 붙는다. ||로 하면 true + "!", nil + "?"까지 연결됨 — 설계 판단.

구현 7-3. 0으로 나누기

지금은 어떻게 되나? 어떻게 되어야 하나? 런타임 에러로 감지·보고하라.
  • 현재: Double 나눗셈 → IEEE 754. 1/0=Infinity, 0/0=NaN. 조용히 흘러나감.
  • 다른 언어: C=UB, Java(정수)=ArithmeticException, Python=ZeroDivisionError.
java
case SLASH:
  checkNumberOperands(expr.operator, left, right);
  if ((double)right == 0) throw new RuntimeError(expr.operator, "Division by zero.");
  return (double)left / (double)right;
klox에 구현됨 — SLASH 분기에서 divisor == 0.0이면 RuntimeError("Division by zero.").
8장Statements and State

문장(효과)과 상태(변수). Environment에 이름→값을 담는다.

구현 8-1. REPL에서 문장·표현식 모두 받기

문장을 입력하면 실행, 표현식을 입력하면 평가해 값을 보여줘라.
  • REPL 한 줄을 문장으로 파싱해 보고, 세미콜론 없이 끝나면 표현식으로 간주.
  • 문법은 그대로 — 파서의 동작 모드(allowExpression)만 토글.
java
private Stmt expressionStatement() {
  Expr expr = expression();
  if (allowExpression && isAtEnd()) foundExpression = true;   // ; 없이 끝 → 표현식
  else consume(SEMICOLON, "Expect ';' after expression.");
  return new Stmt.Expression(expr);
}
// REPL: 반환이 Expr 면 평가해 출력, List<Stmt> 면 실행

구현 8-2. 초기화 안 된 변수 접근을 런타임 에러로

nil 자동 초기화 대신, 초기화·할당된 적 없는 변수를 읽으면 런타임 에러.

null은 Lox의 nil이라 못 쓴다 → 센티넬 객체로 "미할당"을 표시.

kotlin
// Environment
companion object { val UNINITIALIZED = Any() }      // 미할당 표식

// Interpreter
override fun visitVarStmt(stmt: Stmt.Var) {
  val value = if (stmt.initializer != null) evaluate(stmt.initializer)
              else Environment.UNINITIALIZED         // var a; → 센티넬
  environment.define(stmt.name.lexeme, value)
}
private fun lookUpVariable(name: Token, expr: Expr): Any? {
  val value = if (locals[expr] != null) environment.getAt(locals[expr]!!, name.lexeme)
              else globals.get(name)
  if (value === Environment.UNINITIALIZED)
    throw RuntimeError(name, "Unassigned variable '${'$'}{name.lexeme}'.")
  return value
}
코드결과
var a; print a;Unassigned variable 'a'.
var a; a = 5; print a;5 (할당하면 센티넬이 덮임)
var a = 0; print a;0
klox에 구현·검증 완료.

논술 8-3. 가림 초기화 var a = a + 2;

var a = 1; { var a = a + 2; print a; } — 무엇을, 왜?

책(jlox 8장) 답: 3. 초기화식 a + 2가 평가될 때 안쪽 a는 아직 등록 전이라 바깥 a(=1)를 본다 → 3을 안쪽 a로 정의.

갈림길은 단 하나: 초기화식의 이름이 바깥을 보느냐, 선언 중인 안쪽을 보느냐.

언어결과이유
Lox(jlox 8장) · Rust · Scheme let3초기화식이 바깥 바인딩을 본다(Rust=섀도잉, Scheme let=바깥 스코프)
C미정의(쓰레기값)선언자 이후 이름이 스코프에 들어와 자기 자신을 참조
Java컴파일 에러"초기화되지 않았을 수 있음"
JavaScript letReferenceErrorTDZ — 선언 전 접근 금지
Python대응 안 됨블록 스코프 없음(함수 안이면 UnboundLocalError)
이 레포는 11장 Resolver를 갖춰, 자기참조 초기화를 컴파일 에러("Can't read local variable in its own initializer.")로 막는다 → klox에서 이 프로그램은 3이 아니라 컴파일 에러.
9장Control Flow

if · 논리연산 · while · for. 여기서 Lox는 튜링 완전해진다.

논술 9-1. 분기 없이 분기하기

1급 함수 + 동적 디스패치만으로 조건부 실행을 구현하라. 이 기법을 쓰는 언어를 대라.

분기를 데이터에 대한 디스패치로 바꾼다. 동적 디스패치되는 건 condition이고, then/else는 디스패처에게 건네는 인자(후보)일 뿐이다.

  • 인터페이스 = condition (계약 타입의 참조)
  • 구현체 = true(첫째 선택) / false(둘째 선택)
  • 디스패치 대상 = condition · 인자 = thenFn, elseFn
동적 디스패치 — condition(thenFn, elseFn)
receiver (인터페이스)
true
구현체: 첫째 인자를 고름
→
thenFn (인자)
fun() { print "T"; }
elseFn (인자)
fun() { print "F"; }

처치 불리언을 Lox로 인코딩 — 이 레포에서 T/F 출력 확인:

lox
fun makeTrue()  { fun choose(thenFn, elseFn) { return thenFn(); } return choose; }  // 첫째
fun makeFalse() { fun choose(thenFn, elseFn) { return elseFn(); } return choose; }  // 둘째
fun ifElse(condition, thenFn, elseFn) { return condition(thenFn, elseFn); }         // 위임
ifElse(makeTrue(),  sayT, sayF);   // T
ifElse(makeFalse(), sayT, sayF);   // F
smalltalk
"if 가 문법이 아니라 메시지 — receiver 의 클래스가 분기를 결정"
(n > 0) ifTrue: [ 'pos' ] ifFalse: [ 'neg' ].
max := (a > b) ifTrue: [ a ] ifFalse: [ b ].   "값을 돌려받는 표현식"
(x ~= 0) and: [ (10 / x) > 1 ].                 "블록=지연계산 → 단락평가(0 나눗셈 회피)"
[ i < 10 ] whileTrue: [ i := i + 1 ].           "반복마저 블록 receiver 에 보내는 메시지"

언어: Smalltalk(ifTrue:ifFalse:). 람다 계산법의 처치 불리언도 같은 원리(true = λa.λb.a).

논술 9-2. 함수만으로 반복하기

반복도 재귀로 만들 수 있는데, 어떤 최적화가 전제되어야 하나? 왜? 그런 언어를 대라.

답: 꼬리 호출 최적화(TCO). 같은 팩토리얼을 세 가지로 — 차이는 "호출이 끝난 뒤 할 일이 남았는가" 하나뿐이다.

kotlin
fun factRec(n: Int): Long =                       // ② 일반 재귀
    if (n <= 1) 1L else n * factRec(n - 1)        // 곱셈이 호출 "뒤"에 남음 → 꼬리 아님

tailrec fun factIter(n: Int, acc: Long = 1L): Long = // ③ 꼬리 재귀
    if (n <= 1) acc else factIter(n - 1, acc * n)  // 호출이 "마지막 동작" → 꼬리
스택에서 벌어지는 일 — 프로세스의 모양

③의 모양은 while 루프와 글자 그대로 같다 — TCO란 ③을 기계적으로 루프로 바꾸는 변환. Kotlin tailrec(컴파일 시 검증·변환), Scheme(표준이 TCO 의무화). TCO 없는 런타임(JVM 기본, klox)에선 ③도 스택 오버플로 → 그래서 내장 while이 필요하다.

구현 9-3. break 문 추가

루프 안에서 쓰는 break를 추가하라. 루프 밖 break는 막아야 한다.
  • 파싱: loopDepth로 루프 안인지 추적 → 밖이면 파싱 단계에서 에러. 함수 본문 진입 시 0으로 리셋.
  • 실행: BreakException을 던지고 visitWhileStmt가 catch. for는 while로 디슈가되니 자동 처리.
kotlin
private fun breakStatement(): Stmt {
  val keyword = previous()
  if (loopDepth == 0) error(keyword, "Must be inside a loop to use 'break'.")
  consume(SEMICOLON, "Expect ';' after 'break'.")
  return Stmt.Break(keyword)
}
override fun visitWhileStmt(stmt: Stmt.While) {
  try { while (isTruthy(evaluate(stmt.condition))) execute(stmt.body) }
  catch (_: BreakException) { /* 가장 안쪽 루프 탈출 */ }
}
break 루프 실행기
lox
for (var i = 0; i < 10; i = i + 1) {
  if (i == 3) break;
  print i;
}
